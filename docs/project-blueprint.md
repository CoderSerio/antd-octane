# 工程与文档实施约定

状态：工作草案。与 [RFC](RFC-0001-antd-for-octane.md)、[API 决策](api-decisions.md)、[兼容清单](compatibility.md) 配合使用。

## 已落实

- 单一主包 `antd-octane`，组件位于 `packages/antd-octane/src`，不逐组件发包。
- Octane 原生实现；React 与 antd 只参与开发期对照。
- 固定版本与来源记入 `.sync-upstream.json`，保留第三方许可。
- 全局主题复用 v5 纯 token 算法；组件以静态 CSS、命名 layer 与 CSS 变量消费主题。
- 文档站使用 Octane + Vite 静态构建，按页加载、示例源码按需加载。
- `pnpm check` 和 `pnpm pack:check` 覆盖格式、类型、行为、构建及独立消费；真实浏览器另检验键盘、焦点、主题和窄屏。

## 文档质量标准

参考 Ant Design 与 Antdv Next 的信息架构、空间比例与组件示例表达。保持 64px 顶栏、分组侧栏、可定位的页内目录；正文使用 32px 一级标题、24px 二级标题与 14px 正文。示例区采用两列卡片、嵌线标题、复制/展开操作，窄屏切单列。

每个实现组件必须同时提供：何时使用、可运行 TSX 示例、可复制源码、参数/事件/ref 说明、主题能力及已知差异。指南包含版本前提、可执行的本地接入步骤和框架语法约定。只展示有效入口，不伪造组件数量、版本选项、语言切换或不可运行的在线编辑器。

对齐视觉不代表复制整站运行时。使用系统字体、轻量本地搜索、按页加载和无第三方网络依赖的静态资源。首屏字节量、请求与交互分别检查，不以框架 benchmark 替代本站测量。

## 后续顺序

1. 完成输入与状态切片：Input、Checkbox、受控/非受控行为、原生事件及 ref。
2. 浮层共用能力：portal、定位、焦点管理、键盘、context，再实施 Modal。
3. Form 与 Table 的纵向业务例子；先验证动态规则、校验竞争与 render 回调。
4. 完善真实上游浏览器对照与自动化视觉回归；再评估 SSR 和更多环境。

底层优先评估已有 Octane binding 和框架无关实现；确需移植时独立记录来源。不能为追求数量在多个组件复制浮层或表单 store。

## 尚未完成的周边

Changesets、PR 预览包、npm 发布、在线 playground、自动 API 提取及 SSR 仍为后续工作。当前不宣称这些能力存在。每次发布前应复查支持矩阵、第三方声明、构建产物和安装示例。
